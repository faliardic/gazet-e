# Gazet+E Repository Instructions

Bu dosya repository kökünde bütün Gazet+E V2 çalışmalarına uygulanır ve günlük execution için zorunlu giriş noktasıdır.

## 1. Güncel gerçek ve kaynak otoritesi

- Güncel repository gerçeği: GitHub `main`, current Issue/PR/branch ve owner kararları.
- Kanonik GitHub repository kimliği: `faliardic/gazet-e`.
- Kalıcı ürün ilkeleri ve owner kararları: `project_docs/protocols/GAZETTE_UNIFIED_PROJECT_SOURCE.md`.
- Güncel V2 ürün kapsamı: `project_docs/v2/GAZETTE_MOBILE_V2_SCOPE.md`.
- Güncel yürütme sırası ve tek kanonik queue: `ROADMAP.md`.
- `docs/` klasörü GitHub Pages üretim çıktısıdır; proje yönetimi/protokol kaynağı değildir.
- v1.1 desktop/PDF/static-web implementation mevcut legacy baseline'dır; V2 kararı gelmeden sessizce silinmez veya yeniden yazılmaz.

Sabit SHA, açık Issue/PR, branch veya gate durumu kalıcı protokollerde tutulmaz. Bunlar her görevde GitHub'dan okunur. Sohbet hafızası, eski handoff, release notu veya generated output current GitHub gerçeğini override edemez.

## 2. Yeni görev ve resume

Her yeni görevde:

1. `AGENTS.md` okunur.
2. Current GitHub `main`, açık Issue/PR ve aktif branch doğrulanır.
3. `ROADMAP.md` içindeki tamamlanmamış ilk uygulanabilir queue maddesi bulunur.
4. Yalnız değişen sözleşmenin gerektirdiği scope/protocol kaynağı okunur.

Kullanıcı `devam`, `sırada ne var`, `projeyi ilerlet` veya eşdeğer talimat verdiğinde sohbet hafızasından yeni iş uydurulmaz. Açık production Issue/PR varsa önce onun gerekli gate'leri kapanır. Yoksa kanonik queue'daki ilk uygulanabilir iş seçilir.

Owner queue sırasını veya temel ürün kararını değiştirirse production code başlamadan önce karar GitHub authority'ye truth-sync edilir.

## 3. Aktörler ve sıradaki aksiyon

- **ChatGPT:** GitHub gerçeğini okur, roadmap/Issue/PR koordinasyonu yapar, scope ve gate'leri belirler, review eder.
- **Codex:** repository-local dosya değişikliği, test, analyzer, build, format, Git commit/push ve cihaz otomasyonu açıkça devredilmişse teknik execution yapar.
- **Fatih:** ürün davranışı, görsel kalite ve gerçek cihaz acceptance için nihai PASS/FAIL verir; terminal komutu çalıştırması beklenmez.

Repository-local implementation gerektiğinde ChatGPT sıradaki aktörü açıkça belirtir ve current Issue'yu tekrar etmeyen kısa, exact Codex handoff'u hazırlar.

Her sonuç şu formatla biter:

`Sıradaki aksiyon — <ChatGPT|Codex|Fatih|Yok>: <tek uygulanabilir talimat>.`

## 4. Lane seçimi

Her iş yalnız bir lane kullanır.

### FAST

Dar documentation, copy, küçük UI/presentation veya persistence/API contract'ını değiştirmeyen düzeltme.

Varsayılan: minimum focused validation, changed-path review ve `git diff --check`. Manual mobile acceptance yalnız davranış gerçekten cihaz/gesture'a bağlıysa gerekir.

### STANDARD

Birden fazla modül/ekran, edition contract, reader interaction, API/client entegrasyonu veya orta ölçekli behavior değişikliği.

Varsayılan:

- tek self-contained Issue;
- tek kısa ömürlü branch;
- gerekliyse tek Draft PR;
- focused automated validation;
- aynı production işi kapanmadan stacked production branch açılmaz.

### CRITICAL

Authentication, ödeme, secret/API-key güvenliği, kullanıcı hesabı/verisi, privacy/telemetry, destructive migration, production backend data, store/release/signing, third-party licensing enforcement veya güvenlik açısından geri dönüşü zor değişiklik.

Varsayılan:

- exact Issue ve stop conditions;
- explicit write allowlist;
- branch + Draft PR;
- bağımsız review;
- gerekli security/data/device/release gate'leri;
- destructive veya public release eylemi için ayrıca owner kararı.

Somut CRITICAL trigger yoksa iş gereksiz yere ağır sürece yükseltilmez.

## 5. V2 değişmez ürün sınırları

Aşağıdaki ilkeler owner kararı olmadan feature işi içinde değiştirilemez:

1. V2 mobile-first'tür.
2. Ana ürün hareketi tek dokunuşla **on-demand edition** hazırlamaktır.
3. Ana sunum feed/card listesi değil klasik basılı gazete sayfasıdır.
4. İki primary mode vardır:
   - `Gazete Modu`: tam sayfa, pinch-zoom, pan ve sayfa geçişi;
   - `Okuma Modu`: telefona uygun okunabilir article view.
5. Gazete üzerindeki haberler interaktiftir ve orijinal kaynağa erişim korunur.
6. V2 görünür editoryal haber görselleri AI-generated by default'tur; publisher/RSS fotoğrafı ürün bağımlılığı yapılmaz.
7. AI görseli gerçek olayın kanıt fotoğrafı gibi uydurulmaz. Hassas gerçek olaylarda kavramsal/editoryal temsil kullanılır.
8. Kaynak attribution ve source URL edition contract'ın zorunlu parçasıdır.
9. v1.1 legacy pipeline, Q02 architecture audit sonuçlanmadan kaldırılmaz.
10. Public/product marka `Gazet+E`, masthead `GAZET+E`, kanonik GitHub repository kimliği `faliardic/gazet-e`dir. Python package/import namespace'i `chatgpt_haber` ve CLI komutu `chatgpt-haber` uyumluluk için korunur.

## 6. Mobil gesture ve acceptance kuralı

Gazete okuma deneyimi V2'nin çekirdek ürün davranışıdır ve yalnız widget/unit PASS ile kapanmaz.

İlgili slice en az şunları kanıtlamalıdır:

- pinch zoom doğal ve kararlı;
- zoomed durumda pan, istemsiz page-turn ile çakışmaz;
- minimum zoom yakınında page navigation anlaşılırdır;
- article hit-region tap güvenilirdir;
- Okuma Modu'ndan Gazete Modu'na dönünce kullanıcı bağlamı mümkün olduğunca korunur;
- kaynak linki güvenilir biçimde açılır;
- gerçek cihazda metin/görsel okunabilirliği kabul edilir.

Bu davranışları değiştiren slice için Fatih manual mobile PASS/FAIL gate'i zorunludur.

## 7. AI ve maliyet sınırı

- Mobil client içine provider secret/API key gömülmez.
- Aynı haber için özet/görsel gereksiz yeniden üretilmez; cache/identity tasarımı architecture contract'ın parçasıdır.
- AI output kaynak gerçeği yerine geçmez; headline/summary/source ayrımı korunur.
- AI görsel pipeline'ı provenance, style version, prompt/brief version ve generation metadata'sını izlenebilir tutmalıdır.
- Üçüncü taraf haber metni veya görselini ücretli ürün içinde yeniden yayınlama hakkı varsayılmaz; commercial/legal gate ayrıca doğrulanır.

## 8. Validation ve publication

- Aynı revision üzerinde geçen test gereksiz tekrarlanmaz.
- Full suite her mikro adımda değil milestone/release kapısında çalıştırılır.
- Kod değişikliğinde changed-path/protected-drift review zorunludur.
- PR gerekli ise blocker, scope drift, unresolved review veya required acceptance PENDING iken merge edilmez.
- Generated `docs/` çıktısı yalnız publish işi için değiştirilir; governance dosyaları `project_docs/` altında kalır.

## 9. Scope disiplini

Bir Issue sırasında ihtiyaç yeni queue maddesi gerektiriyorsa mevcut Issue sessizce genişletilmez. Yeni ihtiyaç ROADMAP/Issue olarak kaydedilir ve current work minimum güvenli kapsamıyla tamamlanır veya stop condition uygulanır.
